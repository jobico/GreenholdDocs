Some Orders need two signers.
The two signers must have different administrator IDs and different keys.
The policy of the agent decides when an Order needs a second signer.

## When an Order needs two signers

| Policy value | Effect |
|---|---|
| `SecondSignerRule` | On by default. The Order needs two signers when the agent is a server, when the Order names a tag, or when the Order names more devices than `SecondSignerAbove`. |
| `SecondSignerAbove` | The device count for the rule above. The default is 25. The count is for one Order. |
| `AlwaysSecondSigner` | Every Order needs two signers. |
| `AllowTagRelaxation` | A signed amendment with two signers can make a tag Order follow the device count. |

To see if a device is a server, run `Greenhold.Agent.exe status` on it.
The line `Server` says `yes` or `no`.
A test agent on the Greenhold server is a server too.

:::caution
The limit of 25 devices catches mistakes.
It does not stop an administrator who splits one rollout into many small Orders.
To stop this, turn on `AlwaysSecondSigner`.
:::

See [Policy for agents](/concepts/policy-for-agents/) to set these values.

## Add the second signature

<Tabs syncKey="interface">
<TabItem label="GUI">

The Manager works out from what the devices reported whether a job needs two signers.
You can also ask for a second signer on **New job**, with **Ask a second administrator to sign in any case**.

1. The first administrator makes the job and signs it with Greenhold Admin.
2. The job waits with the state **Waiting for a second administrator**.
3. A second administrator signs in to the Manager and opens the job from **Jobs**.
4. The second administrator reads **What it does** and **Where and when**, and chooses **Sign as the second administrator**.
5. Greenhold Admin shows the Order and who signed it already. The second administrator signs with their own key.

Greenhold Admin adds the second signature to the first one.
Then the Manager sends the job.

![A job that waits for a second administrator](../../../assets/screens/manager-job-second-signer.png)

The Manager and Greenhold Admin refuse these cases:

- The same person signs twice.
- The same administrator ID, key or certificate signs twice.
- A second signature without the first.

</TabItem>
<TabItem label="CLI">

The first administrator signs the Order.
The second administrator adds a signature with their own key:

```
greenhold-sign sign --add-to order.signed --admin-key <key folder 2>\admin.key.json --cert <key folder 2>\admin.cert --out order2.signed
```

The second administrator needs a certified key of their own.
See [Make a second administrator key](/get-started/administrator-keys/#make-a-second-administrator-key).
The hash of the Order does not change.
Store `order2.signed` on the gateway with `order add`.

To see what an agent will do, use `greenhold-sign verify`.
The options `--second-signer-above`, `--always-second-signer` and `--no-second-signer` set the policy for the check.

</TabItem>
</Tabs>

## Tags

A tag is a text that the local policy of a computer gives to it.
Group Policy or Intune sets the `Tags` value.
An Order that names a tag names every device that carries the tag.

An agent cannot count the devices of a tag.
For this reason, an Order for a tag needs two signers.

```json
"targets": { "tag": "lab" }
```

:::note
The gateway does not route Orders for a tag yet.
The command `order add` refuses an Order that names a tag.
Name the device IDs in the Order.

On **New job** in the Manager, a tag adds the devices that report it now.
The job names them one by one.
A device that gets the tag later does not get the job.
:::
